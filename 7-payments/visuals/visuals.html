The x402 request/response flow

No code, no account, no human

Agent requests a resource
↓
Server replies: 402, here's what it costs
↓
Agent signs a payment
↓
Server verifies, settles, returns the resource

Stateless — no session, no stored card, no API key sitting around waiting to leak.

Solana Pay vs. x402

The one people actually confuse

Solana Payx402
Who's payingA human, usually scanning a QR codeSoftware — an agent or another service
Where it livesPoint-of-sale, checkout flowsHTTP requests, API responses
What triggers itA merchant requestAn HTTP 402 status code
What it's forBuying a coffeeAn agent buying an API call

The protocol landscape

Which one is for what

ProtocolBuilt for
x402One piece of software paying another for a discrete thing — API calls, data, compute
AP2Agents proving identity and authorization to each other
ACPAgentic shopping checkouts against merchant catalogs
MPPPre-authorized spending sessions, streamed continuously

Not really competitors — they overlap at the edges but solve different problems.
